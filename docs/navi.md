`smill build navi <file-or-directory>... --out <new-dir> [--shell bash|zsh|fish|nu]`
writes one `<sheet>.cheat` file per sheet to a new directory. It generates text
only: SheetMill never runs navi, a shell or any exported command, and the
renderer package is lint-tested to import no `os/exec`, `syscall`, `plugin` or
network package. Export is one way; reading `.cheat` files back is not supported.

## Authoring

Mark a card with `{.navi}` **and** an explicit `{#id}`. The card must contain
exactly one fenced code block whose language belongs to the chosen profile. Prose,
tables, other cards and layout never reach navi.

````markdown
---
title: SheetMill CLI
tags: [sheetmill, validation]
cheatsheet:
  tool: smill
  navi:
    shell: bash
    cards:
      check-sheet:
        params:
          sheet:
            type: path
            description: Markdown sheet to validate
---

## Validation

### Check a sheet {#check-sheet .navi}

```bash
smill check "<sheet>"
```
````

produces `<sheet-file>.cheat`:

```text
; Generated by SheetMill smill build navi; format 1
; Source: sheet.md
; Title: SheetMill CLI
; Shell: bash
; License: not stated
% smill, sheetmill, validation

; card: check-sheet
# Check a sheet
smill check "<sheet>"
```

- The tag context is `cheatsheet.tool` followed by `tags`; a sheet with neither
  uses its file-derived ID. Tags may not contain commas or line breaks.
- The card title becomes the navi description. `; card:` records the card ID.
- Header values (title, source, license, attribution) are collapsed to one line, so
  they cannot create a navi line of their own.

## Shell profiles

navi runs every snippet through the one shell in its own configuration, and the
fence label does not select it. A build therefore targets one profile and states it
in the header; configure navi's `shell.command` to match. A sheet's
`cheatsheet.navi.shell`, when present, must equal the profile (`NAV006` otherwise).

| Profile | Accepted fence languages | Quote check |
| --- | --- | --- |
| `bash` (default) | `bash`, `sh` | POSIX quotes, `$'…'`, comments |
| `zsh` | `zsh` | as bash |
| `fish` | `fish` | backslash escapes inside single quotes |
| `nu` | `nu`, `nushell` | none; nushell's raw strings are not analysed |

Cards in other languages are skipped with `NAV101`, never reinterpreted. Build
each shell into its own directory.

## Parameters

A placeholder is `<name>` with `name` matching `[a-z][a-z0-9_]{0,31}`. Every
placeholder needs a declaration under `cheatsheet.navi.cards.<id>.params.<name>`
and every declaration must be used. Text such as `<Name>` or `<a-b>` that navi
would read as a variable but SheetMill's grammar rejects is `NAV103`. Redirections
(`< in > out`), heredocs (`<<EOF`) and spaced angle brackets are ordinary shell.

`type` is `string`, `int` or `path`; `description` is an optional single-line
string. These are SheetMill metadata. **navi does not enforce them**: without a
suggestion provider it simply asks for text, and SheetMill adds no quoting, so
quote placeholders as you want them in the command. Choice lists, defaults and
dynamic suggestions (`$ name: command`) are not generated yet. All cards of a sheet
share one navi tag context, where a variable name has one definition, so the same
name declared differently in two cards is `NAV007`.

## Command text

The command is exported byte for byte; SheetMill does not claim to detect dangerous
commands. It refuses (skips the card with `NAV102`) text that would change the
file's structure, verified against navi's `parser.rs` (master at the time of
writing): navi reads a line starting in column 0 with `%`, `@`, `;`, `#` or `$`
as syntax, and a line starting with a code fence toggles snippet mode, even
inside a fence. Indent such a line or restructure the command. Also refused:
carriage returns, NUL and other control characters, invisible or bidirectional
controls, blank lines (navi turns them into separators), a trailing line-continuation
backslash and an unterminated quote. Quote checking is skipped for commands with a
heredoc, whose payload is free text.

## Diagnostics

Card problems are warnings: the card is skipped and the build continues.
Metadata and configuration problems are errors: nothing is written.

| Code | Severity | Meaning |
| --- | --- | --- |
| `NAV001` | error | Unsupported shell profile |
| `NAV006` | error | Invalid or unknown `cheatsheet.navi` metadata, dangling card ID, wrong `shell` |
| `NAV007` | error | One parameter name declared differently in a sheet |
| `NAV101` | warning | `.navi` card skipped: no explicit ID, not exactly one code block, or language outside the profile |
| `NAV102` | warning | Card skipped: unsafe or unbalanced command text |
| `NAV103` | warning | Card skipped: malformed placeholder |
| `NAV104` | warning | Card skipped: placeholder and declarations disagree |
| `NAV105` | warning | License not stated; the header says so |
| `NAV106` | warning | Sheet exported nothing; no file written for it. If no sheet exports, the build fails and writes nothing. |

`REN001` and `IO003` apply as for the other renderers. The output directory must
not exist.

## Verification

Table-driven tests cover every negative case per profile family, with a pure Go
model of navi's line grammar recovering the intended structure from the output, a
fuzz target over command text, golden bytes and the no-execution lint. navi itself
is not run. Behaviour was checked by reading upstream source, not by executing it;
re-check `parser.rs` when upgrading the navi version you use.
